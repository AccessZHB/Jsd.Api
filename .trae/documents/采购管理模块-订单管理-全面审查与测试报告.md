**范围澄清（重要）**：任务截图描述的是「全部/待付款/待发货/待收货/已完成/已关闭/售后中 + 买家/收货人/实付金额/支付方式」的**电商销售订单**页面，代码对应 `inventory/order`（右上角顶级菜单「订单管理」，id=3）；而用户文字指定的「采购管理」是另一套单据（供应商/采购单号/草稿/待入库），对应 `procurement/order`。经查 `sys_menu`：

- 顶级「订单管理」(3) → 订单列表(201) `inventory/order/index`

因此本报告**同时覆盖两套模块**：以截图要求为主线审查「订单管理列表」，并对用户点名的「采购订单（采购管理）」做同等深度的代码审查。

## 二、UI / UX 优化建议报告

1. **信息过载**
   - 列表「商品」列只显示「N 种 / N 件」，没有多行商品明细，用户无法在列表核对买了什么。建议采用「主表 + 可展开行（expand）」：默认收起，展开显示商品名/规格/数量/单价/小计，并给出金额合计；或右侧抽屉展示明细。
   - 列宽总计约 1300px，小屏会横向滚动，建议把「收货地址」「备注」移入展开区。

2. **状态可扫性**
   - 当前 `OrderStatusTag` 已区分颜色，但「待收款/待发货/待收货」这类履约状态缺少角标计数；建议在每个 Tab 上显示数量角标（后端 `/order/page` 的 total 或新增 count 接口），减少反复切换。
   - 支付方式纯文本，建议用轻量 Tag（余额支付/银行转账/货到付款），与金额同列视觉分组。

3. **批量能力缺失**
   - 没有「批量发货」「批量导出」「批量关闭」。B2B 场景下建议：勾选列 + 顶部批量栏；批量发货复用现有发货弹窗（同一物流公司/单号可批量填或逐行填）；批量导出应真正生成 Excel（当前为占位接口）。
   - 「发货」属于高风险动作，建议在弹窗内回显订单号、买家、实付金额，避免发错单。

4. **筛选区**
   - 截图要求「订单号/下单时间/买家/收货人」，当前只有订单号、状态、时间；缺少买家、收货人（后端也未支持）。
   - 「买家」当前展示 `买家#1007` 原始 ID，应展示会员昵称/姓名 + ID，并提供远程搜索下拉。

5. **交互细节**
   - 支付/关闭/确认收货按钮均无防重复点击 loading，连续点击会并发提交；建议统一加 loading + 请求中禁用。
   - `pageSize` 越界被静默改写，建议提示「每页最多 100 条」。
   - 关闭原因使用 prompt，确认按钮与原因输入混在一起；建议独立弹窗（原因、影响提示、二次确认）。

6. **采购订单页**
   - 无状态 Tab / 无批量确认；「查看入库记录」实际打开的是订单详情弹窗，语义与入口不一致，建议改名「详情」或拆出入库记录抽屉。

## 三、代码审查核心风险点清单

### P0（阻断 / 资金与数据正确性）

1. **已删除 SKU 导致订单永久无法支付，异常信息裸奔**
   - 位置：[OrderService.cs#L1566-L1619](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L1566-L1619)（`.FirstAsync()`），[OrderController.cs#L227-L242](file:///f:/WorkSpace/Jsd/Jsd.Api/Controllers/OrderController.cs#L227-L242)（catch 后直接透出 `ex.Message`）。
   - 实测：订单 9024 支付返回 `Sequence contains no elements`。
   - 建议：`FirstOrDefaultAsync` + 明确业务提示「商品已下架/删除，无法支付」；同时禁止物理删除被历史订单引用的 SKU（改为软删除或保留快照）。

2. **支付/关闭/发货/完成缺少并发状态机保护（丢失更新）**
   - 位置：[OrderService.cs#L522-L625](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L522-L625)、[#L702-L745](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L702-L745)、[#L756-L813](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L756-L813)、[#L825-L881](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L825-L881)。
   - 问题：`GetByIdAsync` → 状态判断 → 开启事务，行锁获取发生在判断之后；两个并发请求可同时通过 `Pending`/`Paid` 校验。后果：支付与关闭同时成功（钱扣了单关了）、重复发货、重复累加销量。
   - 建议：事务内 `SELECT ... FOR UPDATE`（EF: `FromSqlRaw` 或显式事务 + 乐观并发令牌 `row_version`），或 `ExecuteUpdateAsync` 带 `Where(OrderStatus==期望值)` 的条件更新并判断 affected 行数。

### P1（功能缺失 / 明显不合规）

3. **买家、收货人筛选与买家名称缺失**
   - 位置：[OrderRepository.cs#L20-L61](file:///f:/WorkSpace/Jsd/Jsd.Api/Repositories/OrderRepository.cs#L20-L61)（仅 orderNo/status/time）、[index.vue#L61-L63](file:///f:/WorkSpace/Jsd/Jsd.Web/src/views/inventory/order/index.vue#L61-L63)（`买家#{{ buyerId }}`）。
   - 建议：DTO 增加 `BuyerName`（按 `BuyerId` 批量 join `mem_member`，一次查询避免 N+1）；查询参数增加 `buyerId` / `receiverKeyword`。

4. **列表无商品多行展示、金额合计**
   - 位置：[index.vue#L72-L78](file:///f:/WorkSpace/Jsd/Jsd.Web/src/views/inventory/order/index.vue#L72-L78) 仅统计 `itemCount/totalQuantity`。
   - 建议：展开行按需请求 `/order/{id}/detail`（懒加载，避免列表 N+1），或列表接口返回精简 `items[]`（限 3 条 + more）。

5. **导出为占位实现**
   - 位置：[OrderService.cs#L1259-L1274](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/OrderService.cs#L1259-L1274)、[index.vue#L388-L401](file:///f:/WorkSpace/Jsd/Jsd.Web/src/views/inventory/order/index.vue#L388-L401)。

6. **支付/完成/创建接口缺少按钮级权限**
   - 位置：[OrderController.cs#L200-L256](file:///f:/WorkSpace/Jsd/Jsd.Api/Controllers/OrderController.cs#L200-L256)（`pay` / `complete` / `create` 无 `[Permission]`），仅 `[Authorize]`。
   - 风险：任意后台账号均可改订单资金/履约状态。建议与 `OrderPermissions.Pay/Complete/Create` 对齐并在 Controller 标注。

### P2（性能 / 可维护性）

7. **订单号模糊查询走全表扫描**
   - `order_no.Contains(kw)` 无法命中 `uk_order_no`；百万级 + 组合筛选会慢查询。建议 `StartsWith` 或倒排/ES；补 `(order_status, create_time)` 复合索引（当前只有单列索引）。

8. **采购订单详情每次全量统计入库明细**
   - 位置：[PurchaseOrderService.cs#L179-L191](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/PurchaseOrderService.cs#L179-L191)：`GetConfirmedReceivedAsync()` 未按 `orderId` 过滤，每次查看详情都会把**全库已确认入库明细**拉出来分组。数据量上来后是明显慢 SQL。建议按 `order.Items` 的 `OrderItemId` 过滤。

9. **采购订单确认/作废无事务、无并发控制**
   - 位置：[PurchaseOrderService.cs#L356-L404](file:///f:/WorkSpace/Jsd/Jsd.Api/Services/PurchaseOrderService.cs#L356-L404)。建议条件更新 `WHERE id=? AND status=0` 并校验影响行数。

10. **采购管理 Controller 完全没有按钮级权限**
    - [PurchaseOrderController.cs#L30-L115](file:///f:/WorkSpace/Jsd/Jsd.Api/Controllers/PurchaseOrderController.cs#L30-L115) 全部只有 `[Authorize]`；前端 `v-permission` 只是展示层，接口仍可被越权调用。

11. **金额来源**
    - 列表实付金额读取 `trx_order.pay_amount`（下单时持久化，未按当前 SKU 价重算），满足「不随改价变化」；但**未按规范读 `order_price_snapshot`**。明细单价是 `trx_order_item` 快照，正确。
    - 建议：列表/详情金额增加与快照的一致性校验（或补充说明 pay_amount 即订单级快照），防止后续数据修复造成金额分叉。

12. **前端防重复提交**
    - [index.vue#L343-L386](file:///f:/WorkSpace/Jsd/Jsd.Web/src/views/inventory/order/index.vue#L343-L386) 支付/完成/关闭无 loading 与按钮禁用，叠加后端竞态会放大问题。

### 7.4 遗留 · sys_menu 权限数据缺口（部分已补种）
